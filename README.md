# Metro Medical Stock — ระบบคลังเครื่องมือแพทย์

ระบบรับเข้า / จ่ายออก / ตัดสต็อกด้วยการสแกนบาร์โค้ด ติดตาม Lot / Serial / วันหมดอายุ
สำหรับ **บริษัท เมโทร เมดิคอล จำกัด** · ใช้ได้ทั้งคอมพิวเตอร์ เครื่องยิงบาร์โค้ด (USB / PDA) และมือถือ (กล้อง)

| ส่วน | ใช้อะไร | ค่าใช้จ่ายเริ่มต้น |
|---|---|---|
| โค้ด | GitHub | ฟรี |
| ฐานข้อมูล + ล็อกอิน + ฟังก์ชันฝั่ง server | Supabase (PostgreSQL) | แพ็กเกจ Free ใช้ได้ |
| หน้าเว็บ (https) | Netlify | แพ็กเกจ Free ใช้ได้ |

> ข้อสังเกตแพ็กเกจ Free ของ Supabase: โปรเจกต์ที่ไม่มีการใช้งาน 7 วันจะถูกพักไว้ (กด Restore ได้) และไม่มีสำรองข้อมูลอัตโนมัติ ถ้าใช้งานจริงทุกวันแนะนำแพ็กเกจ Pro

## สิ่งที่ระบบทำได้

- **ล็อกอิน + สิทธิ์ 5 ระดับ** ผู้ดูแลระบบ · หัวหน้าคลัง · เจ้าหน้าที่คลัง · ฝ่ายขาย (ดูอย่างเดียว) · บัญชี/ผู้บริหาร (ดูอย่างเดียว) — บังคับที่ฐานข้อมูล (Row Level Security)
- **รับเข้า** สแกน GS1-128 / GS1 DataMatrix แล้วได้ GTIN + Lot + วันหมดอายุทันที · รับของอายุสั้นกว่ากำหนดต้องให้หัวหน้าอนุมัติ · รับของหมดอายุไม่ได้
- **จ่ายออก / ตัดสต็อก** เลือก Lot ตาม FEFO ให้อัตโนมัติ · ห้ามจ่ายของหมดอายุ · ห้ามยอดติดลบ · ข้าม FEFO ได้เมื่อใส่เหตุผล (ต้องอนุมัติ) · เตือนเมื่อของอายุเหลือน้อยกว่าที่โรงพยาบาลกำหนด
- **ปรับยอด / โอนย้ายคลัง (ฝากขาย, Demo, กักกัน) / ตัดทำลาย-คืนซัพพลายเออร์** พร้อมคิวอนุมัติ
- **ตรวจนับสต็อก** สแกนนับ หรือดึงรายการทั้งคลัง · นับแบบไม่เห็นยอดระบบได้ · ระบบสร้างผลต่างและปรับยอดหลังอนุมัติ
- **เอกสารทุกใบมีเลขที่อัตโนมัติ** (IN-2569-0001 …) · พิมพ์ได้ · ยกเลิกได้โดยไม่ลบประวัติ (ระบบสร้างรายการกลับยอด)
- **การ์ดสินค้า + ทะเบียนคุมเครื่องมือเครื่องใช้** ส่งออก Excel รูปแบบเดียวกับไฟล์เดิม
- **แดชบอร์ดวันหมดอายุ** แยกช่วง หมดแล้ว / ≤30 / 31–90 / 91–180 วัน · มูลค่าเสี่ยงรายเดือน · แจ้งเตือนทุกเช้าทางอีเมลและ LINE
- **รายงาน 9 แบบ** (สรุปคงเหลือ, ทะเบียนคุมทุกสินค้า, ความเคลื่อนไหว, มูลค่าสต็อก, วันหมดอายุ, ยอดจ่ายตามลูกค้า, สินค้าเคลื่อนไหวช้า, ผลตรวจนับ, Audit log) → Excel / พิมพ์
- **พิมพ์ฉลากบาร์โค้ด** GS1-128 / DataMatrix / รหัสภายใน + ป้ายตำแหน่งชั้นวาง
- **นำเข้า Excel** ทั้งไฟล์ทะเบียนคุมเดิม (ชีต "สรุป") และไฟล์แม่แบบที่มี Lot / วันหมดอายุ
- **ข้อมูลเริ่มต้น**: สินค้าจริง 21 รายการ + ยอดยกมา ณ 13/09/2569 จากไฟล์ Excel (รวม 11,904 หน่วย มูลค่า ฿1,144,050)

## ขั้นตอนขึ้นระบบจริง (ประมาณ 30–45 นาที)

### 1) GitHub — เก็บโค้ด

1. เข้า <https://github.com> → **New repository** → ตั้งชื่อ เช่น `metro-medical-stock` → เลือก **Private** → Create
2. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ (ลากวางในหน้า repo ได้ หรือใช้คำสั่ง)
   ```bash
   git init && git add . && git commit -m "Metro Medical Stock v1"
   git branch -M main
   git remote add origin https://github.com/<บัญชี>/metro-medical-stock.git
   git push -u origin main
   ```

### 2) Supabase — ฐานข้อมูลและล็อกอิน

1. เข้า <https://supabase.com> → **New project** → Region เลือก **Southeast Asia (Singapore)** → ตั้งรหัสผ่านฐานข้อมูล (เก็บไว้)
2. ไปที่ **SQL Editor** → **New query** แล้วรันทีละไฟล์ตามลำดับ (คัดลอกทั้งไฟล์ วาง กด Run):
   1. `supabase/migrations/20261116000001_schema.sql`
   2. `supabase/migrations/20261116000002_functions.sql`
   3. `supabase/migrations/20261116000003_rls.sql`
   4. `supabase/seed.sql` ← สินค้า 21 รายการ + ยอดยกมา
3. **Authentication → Sign In / Providers → Email**: ปิด **Allow new users to sign up** (ให้ผู้ดูแลเป็นคนสร้างผู้ใช้เท่านั้น)
4. **Authentication → Users → Add user → Create new user**: ใส่อีเมล + รหัสผ่านของผู้ดูแลระบบ ติ๊ก *Auto Confirm User*
   → **ผู้ใช้คนแรกจะเป็น "ผู้ดูแลระบบ" อัตโนมัติ**
5. **Project Settings → API** จดค่า 2 ค่า: `Project URL` และ `anon public` key (หรือ Publishable key)

### 3) Netlify — เปิดหน้าเว็บ

1. เข้า <https://app.netlify.com> → **Add new site → Import an existing project → GitHub** → เลือก repo
2. Build settings จะอ่านจาก `netlify.toml` อัตโนมัติ (Publish directory = `web`)
3. **Site configuration → Environment variables** เพิ่ม
   - `SUPABASE_URL` = Project URL จากข้อ 2.5
   - `SUPABASE_ANON_KEY` = anon public key จากข้อ 2.5
4. **Deploys → Trigger deploy** → เปิดลิงก์ `https://<ชื่อ>.netlify.app` แล้วล็อกอินด้วยผู้ดูแลระบบ
5. กลับไป Supabase → **Authentication → URL Configuration** → ใส่ Site URL = ลิงก์ Netlify (ใช้กับอีเมลลืมรหัสผ่าน)
6. (ถ้ามีโดเมนบริษัท) Netlify → **Domain management** → เพิ่มโดเมน เช่น `stock.metromedical.co.th`

ทุกครั้งที่แก้โค้ดแล้ว push ขึ้น GitHub — Netlify จะ deploy ให้อัตโนมัติ

### 4) Edge Functions — สร้างผู้ใช้ และแจ้งเตือนวันหมดอายุ

ติดตั้ง Supabase CLI (<https://supabase.com/docs/guides/cli>) แล้วรันในโฟลเดอร์โปรเจกต์:
```bash
supabase login
supabase link --project-ref <project-ref>        # ดูได้จาก Project URL
supabase functions deploy admin-create-user
supabase functions deploy expiry-alert
```
(หรือสร้างในหน้า Supabase → Edge Functions → Deploy a new function → วางโค้ดจาก `supabase/functions/*/index.ts` และ **ปิด Verify JWT** เพราะฟังก์ชันตรวจสิทธิ์เองในโค้ด)

**Secrets** (Edge Functions → Secrets) สำหรับการแจ้งเตือน:

| ชื่อ | ใช้ทำอะไร |
|---|---|
| `CRON_SECRET` | ข้อความลับยาว ๆ ที่คุณตั้งเอง ใช้ยืนยันว่าตัวตั้งเวลาเป็นคนเรียก |
| `APP_URL` | ลิงก์ Netlify เช่น `https://xxx.netlify.app` (ใส่ลิงก์ในข้อความแจ้งเตือน) |
| `RESEND_API_KEY` | (ถ้าส่งอีเมล) สมัครที่ <https://resend.com> |
| `ALERT_FROM` | (ถ้าส่งอีเมล) ผู้ส่ง เช่น `Metro Medical Stock <stock@โดเมนบริษัท>` (ต้องยืนยันโดเมนใน Resend) |
| `LINE_CHANNEL_ACCESS_TOKEN` | (ถ้าส่ง LINE) จาก LINE Official Account → Messaging API (LINE Notify ปิดบริการแล้ว) |

แล้วไปหน้าเว็บ → **ตั้งค่า → การแจ้งเตือน** ใส่อีเมลผู้รับ และ LINE userId/groupId → กด **ทดสอบส่งแจ้งเตือนตอนนี้**

### 5) ตั้งเวลาแจ้งเตือนทุกเช้า 08:00 น.

Supabase → **Database → Extensions** เปิด `pg_cron` และ `pg_net` แล้วรันใน SQL Editor (แทนค่า `<project-ref>` และ `<CRON_SECRET>`):
```sql
select cron.schedule(
  'expiry-alert-daily',
  '0 1 * * *',                                   -- 01:00 UTC = 08:00 น. เวลาไทย
  $$ select net.http_post(
       url     := 'https://<project-ref>.supabase.co/functions/v1/expiry-alert',
       headers := jsonb_build_object('Content-Type', 'application/json', 'x-cron-secret', '<CRON_SECRET>'),
       body    := '{}'::jsonb) $$
);
```
ยกเลิก: `select cron.unschedule('expiry-alert-daily');`

## เริ่มใช้งานจริง (แนะนำ)

1. ผู้ดูแลระบบ: **ตั้งค่า → ข้อมูลบริษัท** ใส่เลขผู้เสียภาษี ที่อยู่ เลขใบอนุญาต (แสดงบนเอกสารและทะเบียนคุม)
2. **ตั้งค่า → คลัง** เพิ่มคลังฝากขายของแต่ละโรงพยาบาล / Demo (ถ้ามี)
3. **ตั้งค่า → ซัพพลายเออร์ / ลูกค้า** ใส่โรงพยาบาลพร้อม "รับอายุขั้นต่ำ"
4. **ผู้ใช้ & สิทธิ์** สร้างบัญชีพนักงาน
5. **สินค้า** ใส่ GTIN ของแต่ละสินค้า (หรือสแกนบาร์โค้ดตอนรับเข้า ระบบจะถามให้ผูกครั้งแรก) และจุดสั่งซื้อ
6. **ตรวจนับเริ่มระบบ**: ไฟล์เดิมไม่มี Lot / วันหมดอายุ ยอดจึงอยู่ใน Lot "ยอดยกมา"
   - ทางที่ง่ายที่สุด: นับของจริงแล้วกรอก **ไฟล์แม่แบบ** (ตั้งค่า → นำเข้า Excel → ดาวน์โหลดไฟล์แม่แบบ) ที่มีคอลัมน์ Lot / วันหมดอายุ
     → ทำ **ปรับยอด** ลด "ยอดยกมา" เป็น 0 แล้ว **นำเข้า** ไฟล์แม่แบบ
   - หรือใช้หน้า **ปรับยอด**: เลือก Lot "ยอดยกมา" ใส่ −จำนวน และเพิ่มบรรทัด "+ Lot ใหม่" ใส่ Lot/วันหมดอายุจริง +จำนวน (ยอดรวมเท่าเดิม)
7. สินค้ารหัส **0029017** (Redon probe CH 8): ไฟล์เดิมช่องคงเหลือเป็น `#REF!` ระบบใช้ยอดรับ 2,200 ไว้ — ควรนับยืนยัน

## อุปกรณ์

| อุปกรณ์ | ตั้งค่า |
|---|---|
| เครื่องยิง USB / ไร้สาย | โหมด Keyboard (HID) · ส่ง **Enter** ท้ายรหัส · เปิดอ่าน GS1 ให้ส่ง FNC1 เป็นอักขระ GS (ASCII 29) · คีย์บอร์ดภาษาอังกฤษ |
| PDA Android (Zebra / Honeywell / Urovo ฯลฯ) | Keyboard Wedge + Enter · เปิดเว็บใน Chrome → เมนู → **เพิ่มลงในหน้าจอหลัก** |
| มือถือ | กดปุ่ม **กล้อง** · อนุญาตกล้องครั้งแรก (ต้องเปิดผ่าน https — Netlify เป็น https อยู่แล้ว) |
| เครื่องพิมพ์ฉลาก | ตั้งขนาดกระดาษในไดรเวอร์ให้ตรงฉลาก (เช่น 50×30 มม.) แล้วพิมพ์จากหน้า "พิมพ์ฉลากบาร์โค้ด" |

ทดสอบเครื่องสแกนได้ที่ **ตั้งค่า → อุปกรณ์สแกน**

## ความปลอดภัย

- กฎทั้งหมด (สิทธิ์, FEFO, ห้ามติดลบ, อนุมัติ) อยู่ในฐานข้อมูล — แก้หน้าเว็บก็ข้ามไม่ได้
- การตัดสต็อกทำผ่านฟังก์ชัน `post_document` เท่านั้น ผู้ใช้เขียนตารางความเคลื่อนไหวตรง ๆ ไม่ได้ · ล็อกตามสินค้ากันตัดซ้อนจากหลายเครื่อง
- ห้ามนำ **service_role key** ไปใส่ในหน้าเว็บหรือ GitHub — ใช้เฉพาะใน Edge Function (Supabase ใส่ให้อัตโนมัติ)
- ปิดการสมัครเองใน Supabase (ข้อ 2.3) · ผู้ใช้ที่ลาออก: ปิดใช้งานแทนการลบ ประวัติยังอยู่
